# 02. Dataset

*Paper-ready source for Methodology Chapter 3.2.*

## Primary Data Source

**The Technical Debt Dataset, version 2.0** (Lenarduzzi, Saarimaki, Taibi 2019).

- 33 Apache Software Foundation Java projects
- Master-branch history only (V2 improvement over V1)
- 78,000+ commits analyzed
- 1.8M SonarQube issues
- Jira issue tracker data linked via commit messages
- SZZ fault-inducing commits via SZZUnleashed
- Refactoring detection via Refactoring Miner

## Tables Used

| Table | Purpose in this study |
|-------|-----------------------|
| `SONAR_MEASURES` | Static code metrics (features) |
| `SONAR_ISSUES` | Rule violations; severity baseline labels |
| `GIT_COMMITS` | Temporal split; historical features |
| `GIT_COMMITS_CHANGES` | Per-file churn aggregates |
| `JIRA_ISSUES` | Confirm bug-fix linkage for consequence labels |
| `SZZ_FAULT_INDUCING_COMMITS` | SZZ baseline labels |
| `REFACTORINGS` | (optional) qualitative validation |

Exact schema details are inventoried in Stage 1
(`results/tables/db_schema.csv`).

## Project Inclusion Criteria

- Minimum 500 pre-snapshot master-branch commits
- Minimum 100 post-snapshot master-branch commits within the 6-month window
- At least one `SONAR_MEASURES` snapshot at or before `t`

Projects failing any criterion are excluded and listed in Table 3.1 with
justification.

## Why No External Data

External GitHub scraping is not required because:
1. The dataset is ~5x larger than comparable sister-paper corpora
2. SZZ and Jira linkage are pre-computed (eliminates tool-chain risk)
3. Reproducibility is guaranteed by a single citable artifact

A small optional external-validity extension (Stage 10, if time permits)
adds 1-2 non-Apache Java projects, run with PyDriller, to strengthen
threats-to-external-validity discussion.
